## Accepted Study Package

Supply either an unpacked study directory or a `.zip` archive. The package
must contain one `meta_study.txt` and one sample-clinical meta file. Its
`data_filename` identifies the required sample table. A patient-clinical table
is optional; when absent, patients are derived from the sample table.

Convert-Pheno also reads case lists under `case_lists/`. Patient IDs, sample
IDs, clinical links, study identifiers, and case-list members are checked
before mapping. Unknown references and duplicate identifiers stop the
conversion instead of producing disconnected records.

The package is processed in memory. ZIP files are read directly and are not
extracted to disk.

## Clinical Mapping

The built-in mapping provides the stable cBioPortal structure:

- study metadata becomes a BFF `dataset`
- patient rows become BFF `individuals`
- sample rows and patient links become BFF `biosamples`
- case lists become BFF `cohorts`
- `ONCOTREE_CODE` becomes an `OncoTree:` disease and histological-diagnosis term

`SAMPLE_TYPE` values such as `Primary` are cBioPortal source categories, not
necessarily ontology concepts. Convert-Pheno therefore preserves the exact
value under `info.cbioportal.sample` but leaves `sampleOriginType` as
`Not Available` unless an optional mapping supplies a curated ontology term.
A syntactically valid CURIE is not treated as sufficient evidence of ontology
meaning.

Use `--no-source-info` to omit the copied patient, sample, and study metadata.
Structural links and mapped semantics remain.

## Optional Mapping File

A Mapping V2 file with `source.profile: cbioportal` can map additional patient
and sample columns. `beacon.individuals` evaluates patient attributes;
`beacon.biosamples` evaluates sample attributes. Source `PATIENT_ID` and
`SAMPLE_ID` values cannot be rewritten because sample links and case lists
depend on them.

See [Working with Mapping Files](mapping-files) and the
[cBioPortal to BFF mapping](cbioportal2bff). The attributed test package and
mapping example are under
[`t/cbioportal2bff/in`](https://github.com/CNAG-Biomedical-Informatics/convert-pheno/tree/main/t/cbioportal2bff/in).

## Run A Conversion

Write all implemented BFF entities:

```bash
convert-pheno -icbioportal study/ \
  -obff --entities individuals biosamples datasets cohorts \
  --out-dir bff_out/
```

Read the same package from ZIP and produce Phenopackets:

```bash
convert-pheno -i cbioportal study.zip \
  -o pxf phenopackets.json
```

Write supported OMOP-CDM tables:

```bash
convert-pheno -icbioportal study/ \
  -oomop --out-dir omop_out/ \
  --ohdsi-db
```

The route is available through the CLI, Perl module, and Python binding. It is
not exposed through the HTTP(s) API because a cBioPortal input is a filesystem
package rather than one self-contained JSON document.
