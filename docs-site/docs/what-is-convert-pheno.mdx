`Convert-Pheno` is **open-source software** for converting clinical and phenotypic data between commonly used exchange models. It is mainly designed for file-based transformations and reproducible batch conversion.

## What Problem It Solves

Clinical datasets often arrive in formats that are useful inside one project but hard to reuse elsewhere. A REDCap export, an OMOP database dump, and a Phenopacket can describe overlapping clinical concepts while using different structures, identifiers, and nesting rules.

`Convert-Pheno` provides a controlled conversion layer so users can:

- transform supported source formats into Beacon-compatible `BFF`
- generate Phenopackets v2 or OMOP-CDM outputs when supported
- use mapped `CSV` records as input for ETL into `BFF`, `PXF`, or supported OMOP-CDM tables
- keep source provenance in `info` for auditability
- inspect ontology lookup results through optional search audit files

## How It Works

Most routes normalize data through `BFF`, which acts as the **internal target model**. That does not mean the final output must be `BFF`: depending on the selected route, the output can be Beacon entities, Phenopackets, OMOP-CDM CSV tables, flattened JSON, flattened CSV, or JSON-LD.

For mapping-file conversions such as `CSV`, `REDCap`, and `CDISC-ODM`, the mapping file defines how source columns become Beacon `individuals` fields and first-class `biosamples`, plus optional defaults for synthesized `datasets` and `cohorts`.

For structured standards such as `PXF`, `OMOP-CDM`, CDISC `Dataset-JSON`, FHIR
R4 Bundles, and openEHR canonical compositions, the converter uses source-specific mapping code
rather than a user mapping file.

## CSV-based ETL

When `CSV` is the input, Convert-Pheno can be used for mapping-driven ETL. A project mapping file maps source columns to `BFF`; the same CLI run can then write `BFF`, `PXF`, or supported OMOP-CDM tables. Users do not need to create the intermediate `BFF` file themselves.

The mapping still has to be defined and reviewed before generated output is loaded into a target system.

Supported routes are covered by automated regression tests and target-format
checks where practical. Independent use across diverse real-world datasets
varies by route. openEHR, Dataset-JSON, FHIR, and generic CDISC-ODM input
profiles remain experimental because their implemented source profiles have
limited independent dataset coverage; the established REDCap ODM profile is
tracked separately.

## Main Interfaces

Most users should use the [command-line interface](use-as-a-command-line-interface), especially for real files, mapping files, OMOP tables, audit logs, and multi-entity BFF output.

For developers who need to call Convert-Pheno from other code, the project also exposes:

- [Module usage](use-as-a-module) for local Perl or Python code
- [HTTP(s) API usage](use-as-an-api) for self-contained JSON requests
