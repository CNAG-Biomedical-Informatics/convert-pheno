**Category:** EHR interoperability and information modelling

[openEHR](https://www.openehr.org) defines vendor-neutral clinical information
models and canonical representations for electronic health records.
Convert-Pheno reads the **implemented EHRbase-oriented canonical composition
profile** and groups compositions by patient.

:::note[Implementation status]
Implemented and regression-tested. Experimental status reflects limited
independent validation across openEHR templates and deployments.
:::

## openEHR As Input

Convert-Pheno accepts EHRbase-style canonical compositions as JSON or YAML,
including gzip-compressed files. Input can be a patient envelope containing a
`compositions` array, one raw composition, or multiple files supplied in one
request. A mapping file is not required.

Files are grouped by resolved patient identity before conversion. Compositions
for one patient become one output record; distinct embedded patient identifiers
can produce multiple records. Conversion fails when a stable patient identifier
or administrative gender cannot be resolved.

Use [openEHR conversion recipes](conversion-recipes#openehr-input-bff-output)
for BFF and PXF commands.

## Implemented Clinical Content

The current profile maps:

- administrative gender to `sex`
- problems and diagnoses to `diseases`
- laboratory results and body temperature to `measures`
- symptom screening to `phenotypicFeatures`
- procedures to `interventionsOrProcedures`
- medication actions to `treatments`

External codes are retained as CURIEs. Uncoded text receives a local
`openEHR:` identifier when the target term requires both an identifier and a
label. Source compositions are preserved under `info.openehr.compositions`
for traceability.

## Current Boundaries

The openEHR route currently writes BFF or PXF. It does not directly write OMOP,
CSV, flattened JSON, or JSON-LD, and it does not yet map first-class Beacon
`biosamples`. Coverage depends on the archetypes and node names represented in
the implemented canonical profile.

For field-level behavior and omissions, see the
[openEHR to BFF mapping](openehr2bff). Regression inputs are indexed in the
[`t/` fixture guide](https://github.com/CNAG-Biomedical-Informatics/convert-pheno/tree/main/t).
